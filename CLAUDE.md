# PodcastRemotionAnimation

Пайплайн, превращающий аудиофайл подкаста в вертикальное (1080×1920)
видео со сплит-скрин раскладкой:

- **верх** — слайд текущей темы: насыщенный цветной фон (цвет активного
  спикера), крупная SVG-иллюстрация в «стикер»-стиле (жирная обводка,
  твёрдая тень) + крупный центрированный заголовок и тезисы, с мягким
  fade+slide переходом между сценами;
- **низ** — два персонажа-ведущих: AI-сгенерированные (Canva) погрудные
  портреты на фоне фото студии, без рамок/карточек — активный спикер
  показывается **яркостью** (не размером): активный на 100%, неактивный
  притемнён до 40% («уходит в тень»), плюс лёгкая процедурная анимация рта;
- по центру, на стыке половин — пословные субтитры на тёмной плашке с
  тонкой белой рамкой (для читаемости на любом фоне под ними), с
  подсветкой текущего слова.

Слайды, вёрстка, анимации, субтитры — только средствами Remotion
(React/SVG/CSS), без сторонних инструментов. **Исключение** — портреты
ведущих и фон студии: по явному запросу пользователя портреты
сгенерированы через Canva AI (`generate-image` + `remove-background`),
фон студии — фото, добавленное пользователем вручную. Обе вещи — внешние
ассеты в `public/`, не код.

## Статус проекта (важно для след. сессии)

- ✅ **Готово, проверено и полностью отрендерено**: аудио →
  транскрипт+диаризация (WhisperX) → нормализация → сцены (32 шт. для
  реального эпизода) → верхняя половина (цветные слайды-иллюстрации по

  новый эпизод (нужно будет придумать категории иллюстраций заново или
  переиспользовать 8 существующих, см. «Верхняя половина»), либо точечные
  правки текущего дизайна.
- Дневник проекта (хронологический, все шаги/баги/находки, по разделам
  `## N. Заголовок`) ведётся не как локальный файл, а как документ
  Claude Docs:
  https://claude.ai/artifact/PfZJu5waGn92W7CNhw8WUk — дописывайте туда
  новые разделы по ходу или в конце сессии (через MCP-коннектор Claude
  Docs, инструменты `mcp__claude_ai_Claude_Docs__*`), а не полагайтесь
  только на память/этот файл. `CLAUDE.md` — компактный актуальный срез
  архитектуры и решений, держите его в актуальном состоянии по ходу

  хронология для восстановления деталей/воспроизведения шагов.

## Пайплайн

```
аудио → WhisperX (транскрипт + диаризация) → normalize_transcript.mjs
      → transcript.md → Claude Code генерирует scenes.json → Remotion render
```

Подробный пошаговый гайд с командами — в `scripts/README.md`. Коротко:

1. `scripts/transcribe_diarize.py` — WhisperX локально (Python venv в
   `scripts/.venv`, нужен разовый HuggingFace-токен для pyannote
   diarization — кладётся в `scripts/.hf_token`, гитигнорится).
2. `scripts/normalize_transcript.mjs` — сырой JSON → `public/data/<ep>.captions.json`
   (формат `Caption[]` из `@remotion/captions`) + компактный
   `public/data/<ep>.transcript.md` с метками спикеров + `public/data/<ep>.turns.json`
   (точные границы реплик — драйвер активности в `HostsRow`).
3. Генерация `public/data/<ep>.scenes.json` — задача для Claude Code:
   прочитать `transcript.md`, порезать на смысловые куски 15–30 сек,
   заполнить схему `scenesFileSchema` из `src/schema.ts`. Делается вручную
   на эпизод (не автоматизировано скриптом), чтобы контролировать качество
   разбивки. Для эпизода `podcast_remotion_hyperframes` уже сделано (32 сцены).
4. Положить аудио в `public/audio/<ep>.mp3` и рендерить:
   `npx remotion render PodcastVideo-hyperframes out/<ep>.mp4`
   (пропсы уже зашиты в `Composition.tsx`; пример команды с явными
   `--props` — в `scripts/README.md`, нужен для нового эпизода).

## Архитектура composition (`src/`)

- `schema.ts` — zod-схемы: `Scene`, `ScenesFile`, `Turn`, `CaptionData`,
  `HostConfig` (`label`, `color`, `photoBase`), `PodcastVideoProps`.
  Единый источник истины для формата `scenes.json`/`captions.json`/`turns.json`.
  `Scene.slide` содержит `title`, `bullets`, `icon` (имя иконки
  `lucide-react` — **больше не рендерится**, оставлено как
  референс/фолбэк на будущее) и `category` —
  `slideIllustrationCategorySchema`, один из 8 ключей
  (`spark`/`dataOverload`/`aiReads`/`codeBuilds`/`rhythm`/`comparison`/
  `selfCheck`/`humanAI`), см. «Верхняя половина» ниже.
- `Composition.tsx` — регистрирует **две** композиции:
  - `PodcastVideo` — dev/демо на рукописных sample-данных (`public/data/sample.*`,
    `public/audio/sample.mp3` — сгенерированный ffmpeg плейсхолдер-тон,
    НЕ настоящая речь).
  - `PodcastVideo-hyperframes` — реальный эпизод, все данные настоящие
    (транскрибированы и сгенерированы за эту сессию). Это композиция, на
    которой всё проверялось и которую стоит открывать по умолчанию.

  `calculateMetadata` асинхронно подгружает `scenesUrl`/`captionsUrl`/`turnsUrl`
  (`fetch(staticFile(...))`) и вычисляет `durationInFrames` из реальной
  длительности аудио (`src/lib/getAudioDuration.ts`, через `mediabunny`).
  Если аудио нечитаемо — фолбэк на `endMs` последней сцены.
- `PodcastVideo.tsx` — корневой компонент: `TopicSlides` + `HostsRow` +
  `CaptionsOverlay` + `<Audio>`.
- `components/TopicSlides.tsx` — верхняя половина, финальный дизайн (не
  заглушка) — подробности в разделе «Верхняя половина» ниже.
- `components/HostsRow.tsx` + `HostAvatar.tsx` — нижняя половина, см.
  подробности в разделе «Портреты ведущих» ниже.
- `components/CaptionsOverlay.tsx` — `createTikTokStyleCaptions()` +
  подсветка текущего токена по времени. Короткие фразы (страницы рвутся
  каждые ~1.2 сек по `combineTokensWithinMilliseconds` + разрыв по паузе
  `breakOnSilenceAfterMilliseconds`), длительность показа — `page.durationMs`.
  Текст на тёмной плашке (`rgba(0,0,0,0.7)`) с тонкой белой рамкой
  (1.5px) — добавлено, т.к. фон под субтитрами теперь непостоянный (то
  слайд, то фото студии), плашка обеспечивает читаемость в любом случае.
  Шрифт — 68px (увеличен с исходных 34px по запросу пользователя).

### Верхняя половина: цветные слайды-иллюстрации (`TopicSlides.tsx`)

Прошла несколько итераций по фидбеку пользователя (была: тёмный фон +
мелкий текст + просто иконка → пробовали AI-иллюстрации через Canva, но
`generate-image` уходил в стабильный rate limit → в итоге всё сделано
чисто в коде, SVG/CSS, без внешних ассетов). Финальный дизайн:

> **Заметка про инструменты генерации картинок**: Canva MCP
> (`mcp__claude_ai_Canva__generate-image`) в этой сессии оказался
> неэффективен для генерации иллюстраций — 5 попыток подряд (с паузами)
> упёрлись в `Too many requests`, не сработало ни разу. **Более удачная
> альтернатива, которой стоит пробовать в первую очередь для похожих
> задач** — дизайн-канвас Claude (`Artifact` tool, `action: "quickstart"`,
> `intent: "design"` → тип "Design", `.dc.html`-артборды с живым canvas):
> использовался в этой же сессии, чтобы набросать и сравнить несколько
> вариантов стиля слайда (цветные блоки, стикер-стиль и т.д.) без единого
> запроса к внешнему API — сработал сразу и без лимитов. **Важный
> нюанс**: доступ к этой дизайн-системе — не то, что доступно по
> умолчанию, пользователю нужно было отдельно авторизовать её на своей
> стороне (в этой сессии — локальная команда `/design-login`, результат
> `Design-system access authorized`) **до** того, как `Artifact
> quickstart` с `intent: "design"` стал работать. Не предполагайте, что
> доступ уже есть в новой сессии — если пользователь просит
> сгенерировать иллюстрации/дизайн и Canva снова упирается в лимиты,
> предложите дизайн-канвас Claude как альтернативу, но сначала уточните
> у пользователя, авторизован ли он в текущей сессии (или просто
> попробуйте `quickstart` — если доступа нет, это будет видно из ответа).

- **Фон** — на весь верх, сплошной цвет активного спикера
  (`hosts.host1.color`/`host2.color`, фиолетовый `#7c6cf0` если говорят
  оба), с лёгкими декоративными штрихами-«скоростными линиями» и
  полутоновыми точками (`opacity` 0.13–0.16, статично, не анимируются).
- **Иллюстрация** — не иконка `lucide-react`, а кастомная SVG-картинка в
  «стикер»-стиле: жёсткая тёмно-синяя обводка (`stroke`), плоская заливка,
  твёрдая (не размытая) тень через один общий SVG-фильтр `stickerShadow`
  (`feOffset`+`feFlood`+`feComposite`+`feMerge`) — вешается на `<g>` целой
  группы фигур, а не на каждую фигуру отдельно, поэтому шаблон компактный.
  Полноценную иллюстрацию под каждую из 32 сцен рисовать вручную
  нереалистично, поэтому сцены сгруппированы по **8 темам**
  (`SlideIllustrationCategory` в `schema.ts`), на каждую — одна
  иллюстрация, переиспользуется:
  - `spark` — монитор, разлетающийся кинокадрами (вступление/идея/магия)
  - `dataOverload` — стопка серверов с переполняющимися «катушками»
  - `aiReads` — робот с лупой сканирует ноутбук с waveform/текстом
  - `codeBuilds` — окно кода + вылетающий видео-кадр
  - `rhythm` — вертушка DJ + звуковые полосы + плёнка
  - `comparison` — весы с двумя предметами на чашах
  - `selfCheck` — чек-лист + лупа + круговая стрелка (цикл проверки)
  - `humanAI` — человек и робот дают друг другу пять перед экраном с галочкой

  Категория для каждой сцены реального эпизода прописана вручную в
  `podcast_remotion_hyperframes.scenes.json` (`slide.category`) — при
  разбивке нового эпизода на сцены нужно либо переиспользовать один из
  этих 8 ключей по смыслу темы, либо дорисовать новую функцию
  `IllustrationXxx` в `TopicSlides.tsx` и добавить её в маппинг
  `ILLUSTRATIONS`.
- **Текст** — заголовок 84px/900 (жирный, центр), тезисы 60px (специально
  подогнаны под размер субтитров 68px из `CaptionsOverlay` — «на пару
  пунктов меньше», как попросил пользователь), **без точек-маркеров**
  (были — сначала как отдельный флекс-блок слева, что при переносе тезиса
  на 2 строки визуально «отрывало» точку от центрированного текста; чинили
  через inline-точку перед текстом; в итоге пользователь попросил убрать
  точки вообще — сейчас просто центрированный текст). И заголовок, и
  тезисы — с эффектом «обводка как в комиксах» через стек из 8
  `text-shadow` (`COMIC_OUTLINE`/`COMIC_OUTLINE_WIDE` — сдвиги ±2px/±3px
  по диагоналям тёмно-синим), а не через CSS `-webkit-text-stroke` (не
  везде рендерится одинаково) или SVG-текст.
- **Переход между сценами** — плавный fade + лёгкий вертикальный slide,
  каждый слайд сам анимирует себя на входе/выходе (`enterFrames`/
  `exitFrames`, ~0.45 сек), соседние слайды просто перекрываются по
  времени. **Специально не использован** `<TransitionSeries>` из
  `@remotion/transitions` — он укорачивает общую длительность композиции
  на длину перехода, что рассинхронило бы слайды с реальным таймингом
  сцен/субтитров/аватаров (тайминг завязан на реальную длительность
  аудио через `calculateMetadata`).

### Нижняя половина: портреты, фон студии, активность (`HostsRow.tsx` + `HostAvatar.tsx`)

**Портреты (`public/characters/`)**: `<photoBase>-{closed,half,open}.png` —
AI-сгенерированные (Canva `generate-image` + `remove-background`,
прозрачный фон) погрудные портреты, три состояния рта. `half`/`open`
сделаны через image-to-image редактирование `closed` (тот же
`imageReferences`) для консистентности персонажа между состояниями —
независимая генерация каждого состояния даёт разных людей.

В проекте **два набора**, оба сгенерированы одним рецептом, старый не
удалён:
- `host1-*` / `host2-*` — первая версия, анфас.
- `host1-turned-*` / `host2-turned-*` — **активный** набор (см. `photoBase`
  в обоих `<Composition>` в `Composition.tsx`): персонажи развёрнуты на
  три четверти друг к другу (host1 смотрит вправо, host2 влево — при
  показе рядом выглядит как разговор лицом к лицу) и в наушниках.

Чтобы вернуть анфас-версию — поменять `photoBase` обратно на
`"host1"`/`"host2"`. Рецепт добавления нового ракурса/состояния/
персонажа: 1) базовый портрет с закрытым ртом (явный промпт про
стиль/позу/наушники/фон), 2) image-to-image с тем же media id, промпт
"same character/pose/style/colors/background/headphones, mouth <state>"
на каждое дополнительное состояние, 3) `remove-background` на все,
4) файлы в `public/characters/` под новым `photoBase`.

**Размер и позиция**: портрет 418×519px (это 190×236 «база» + 120% по
явному запросу — т.е. итог 220% от базы, не 120%!). Без рамки/карточки
вокруг — только сам портрет, без подписи с именем (была плашка
`host.label` снизу поверх картинки — убрана по запросу пользователя,
`host.label` в схеме остался, но нигде не рендерится). `HostsRow`
разводит их по краям (`justifyContent:
space-between`, отступ 56px от каждого края — «дальше от центра») и
прижимает по нижнему краю экрана (`alignItems: flex-end`, у `HostAvatar`
нет отдельного transform/scale, так что нижний край портрета = нижний
край контейнера = низ кадра).

**Активность — только яркостью, не размером** (явный запрос
пользователя, ранний вариант с `scale()`-«пампом» и активационным
кольцом убран): `filter: brightness()` на портрете, активный спикер →
100%, неактивный → 40% (`DIM_BRIGHTNESS`), оба анимируются одной и той
же пружиной от `activeSinceFrame` (момент смены реплики из `turns.json`)
— получается единое движение «прожектор переходит с одного на другого».
Была и промежуточная версия с цветной рамкой + полупрозрачной карточкой
вокруг портрета — убрана по следующему запросу пользователя, т.к.
закрывала фон студии (микрофон, вывеску).

**Фон студии (`public/backgrounds/bg_1.png`)**: фото, добавленное
пользователем вручную. Рендерится в `HostsRow` как `<Img>` на всю нижнюю
половину (`object-fit: cover`, `object-position: "center 30%"` — сдвиг
вверх, чтобы в кадр гарантированно попадал микрофон/вывеска, а не только
пустой пол), поверх — лёгкое затемнение `rgba(0,0,0,0.25)` для
консистентности тона с верхней половиной и читаемости подписей. Если
пользователь положит другой файл фона — просто поменять путь в
`HostsRow.tsx` (`staticFile("backgrounds/bg_1.png")`) или добавить новый
`photoBase`-подобный параметр, если фонов станет несколько.

**Анимация рта**: сырая амплитуда (`getWaveformPortion` на оригинальной
дорожке) на этой нормализованной подкаст-записи ведёт себя как грубый
голос/тишина-детектор (насыщается на всю фразу, а не колеблется по
слогам) — напрямую в форму рта её не смапить, будет «повисает открытым».
Поэтому амплитуда используется только как **voice-gate** (`amplitude >
0.05`), а сама смена форм рта (closed→half→open→...) идёт по
**процедурной** анимации — двум наложенным синусоидам разной частоты,
имитирующим ритм слогов (~3-5/сек), пока голос активен. Переключение
между тремя PNG **резкое** (см. gotcha ниже), не кроссфейд.

Если нужно другое соотношение яркости/размера, другой фон, другой
рецепт активности — вся логика в этих двух файлах, компактная (~80-100
строк каждый), проще переписать, чем патчить.

### Gotcha: кроссфейд прозрачных PNG даёт мерцание

Не смешивайте состояния (рта, чего угодно) через плавный CSS
`opacity`-кроссфейд двух слоёв с прозрачным фоном — в середине перехода
(например 50/50) видно сразу два полупрозрачных слоя, и сквозь них
проступает то, что позади (до ~25% на пике) — читается как
мерцание/потемнение. `HostAvatar.tsx` показывает ровно один слой на 100%
непрозрачности за раз (резкое переключение, как в спрайтовой анимации).

### Gotcha: пробелы в субтитрах

`createTikTokStyleCaptions` из `@remotion/captions` решает, разрывать ли
страницу, только когда `text` токена начинается с пробела (проверено по
исходнику пакета) — пробел должен быть **перед** словом, а не после.
Перепутаешь — вся дорожка склеится в один текстовый блок до ближайшего
`pageBreakAfter`. Смотри `withLeadingSpace()` в `normalize_transcript.mjs`.

### Gotcha: `AbsoluteFill` и деление экрана пополам

`<AbsoluteFill>` в Remotion всегда явно ставит `height: 100%` в
inline-style. Если для деления экрана пополам задать только `bottom:
"50%"` (без явного `height`), браузер из-за CSS over-constraint
проигнорирует `bottom`, и элемент останется на всю высоту. **Всегда
указывайте `height` явно** (`height: "50%"` для верхней половины, `top:
"50%", height: "50%"` для нижней) — так и сделано в
`TopicSlides`/`HostsRow`/`CaptionsOverlay`.

### Gotcha: `useWindowedAudioData` + `getWaveformPortion`

`getWaveformPortion` обязательно нужен с `dataOffsetInSeconds` из
`useWindowedAudioData` — без него индекс уезжает мимо буфера окна и
амплитуда считается неправильно. Реальный баг, на который наступили.

### Gotcha: `interpolate()` требует строго возрастающие точки

При кроссфейде слайдов в `TopicSlides.tsx` первая/последняя сцена не
имеет соседа для перекрытия, поэтому казалось логичным занулить
`enterFrames`/`exitFrames` именно для них. Это даёт `interpolate(frame,
[0, 0, x, y], ...)` — две одинаковые точки `0` подряд — и Remotion падает
с `inputRange must be strictly monotonically increasing`. Исправлено
по-другому: `enterFrames`/`exitFrames` **всегда** ненулевые (одна и та же
`t`), а вместо этого не сдвигается `from`/`durationInFrames` в сторону
несуществующего соседа (см. комментарий в коде рядом с `isFirst`/
`isLast`). Общий вывод: если точки `interpolate()` строятся из
вычисляемых переменных, а не захардкожены — проверяйте граничные случаи
(первый/последний элемент), где переменная может обнулиться.

### Gotcha: центрированный текст + точка-маркер во флекс-строке

Ранний вариант тезисов рендерил маркер точкой и текст как два элемента
флекс-строки (`display:flex`, точка + `<span>` текста). Пока текст был в
одну строку — выглядело нормально. На тезисе, который переносится на 2
строки, точка визуально «отрывалась» и уезжала к левому краю контейнера
отдельно от центрированного текста. Причина: у flex-item нет
специального поведения при wrap текста внутри — при обтекании текст
внутри `<span>` центрируется в своей (широкой, почти на весь ряд) рамке,
а точка как отдельный сосед остаётся у истинного левого края этой рамки,
а не рядом с первой строкой текста. Итог обсуждения с пользователем —
точки убраны совсем, тезисы — просто центрированный текст без маркера.
Если понадобится вернуть маркер к центрированному тексту — не выносите
его отдельным flex-элементом, а вставляйте как inline/inline-block
элемент прямо перед текстом внутри одного текстового потока (тогда он
остаётся приклеен к первой строке при переносе).

### Проверка результата: не доверяй превью Studio на глаз

Дважды за сессию визуальная проверка через живое воспроизведение в
Remotion Studio (Play в браузере) вводила в заблуждение — то казался
баг, которого не было в реальном рендере, то казалось, что правка не
применилась (хотя применилась). Причины были разные (лайв-плейбек может
не пересчитывать тяжёлые хуки каждый кадр; кэш вкладки браузера), но
вывод один: **для тонкой проверки анимации/точных значений — рендерь
`npx remotion render` с `--frames=N-M` и смотри кадры напрямую**
(`ffmpeg -i out.mp4 frames/f%03d.png`), а не полагайся на Studio-плеер
или на глаз в скриншоте. Пиксельные измерения через
`mcp__claude-in-chrome__javascript_tool` (`getBoundingClientRect`) —
тоже надёжный способ проверить реальный размер/позицию элемента, не
полагаясь на визуальное впечатление.
